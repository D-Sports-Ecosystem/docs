## Common user journeys

- Superadmin/team-admin lists managed teams and members
- Team manager accesses assigned team pages and updates team-scoped content
- Admin reviews team-level status and assignment coverage

## Team assignment operations

`/api/admin/team-assignments` supports list/create/update/delete patterns for team bindings, with role validation and safety checks.

Behavior expectations:

- Assignment writes require privileged authorization.
- Invalid team/user combinations return explicit error responses.
- Last-owner removal is blocked by guardrails.

## Team member role operations

`/api/admin/teams/{teamId}/members` and `.../{userId}` expose team member lifecycle behavior:

- List members in role-aware order
- Upsert member roles under allowed role envelopes
- Remove members with ownership safety constraints

## Player availability

`PUT /api/admin/players/{playerId}/availability` is platform-admin only. It records manual availability or injury status. Hockey providers do not supply this. Sending a null status clears the player back to available. Do not document provider internals or admin tooling beyond this contract.

## Submission workspace

Team Management uses the same `SubmissionWorkspace` creator and editor for new and existing submissions. Open `/team-mgmt/{teamId}/submissions/new`, choose a saved pack, collectible, or team-default target, and preview a design before creating a draft. **Render new front** in the collectible editor opens this creator with the collectible selected; it no longer creates a draft immediately.

- `GET /api/admin/submissions/templates?teamId=…&selection=latest` selects the latest compatible version per key. Add `targetKind=pack|collectible|team_default`; packs and collectibles require a team-scoped `targetRef`. `sourceHasTransparency=true|false` is only valid for collectible targets. The response may include `recommendedTemplateId` and `unavailableTemplateKeys`. Without `selection`, the endpoint returns all eligible active versions and rejects target-selection parameters.
- Template example images and videos are bundled under `/submission-template-examples/{key}/v{version}/`. These are illustrative examples for that exact version, not renders of your artwork. Missing examples show a fallback; they must not silently use another version's preview. Existing submissions retain their pinned template version.
- For card fronts, send `cardFrontCollectibleId` instead of explicit `templateKey`/`templateVersion`. Optional `expectedTemplateKey` and `expectedTemplateVersion` must be supplied together and only with a card-front target. They assert the previewed recommendation, not a template override. If selection changed, creation returns `409`; refresh the preview before retrying.
- `PATCH /api/admin/submissions/{id}` accepts only `{ "title": "New title" }`. Titles are trimmed and must be 1–120 characters. The authenticated manager must be authorized for the team. IDs or team-scoped slugs are accepted (use `?teamId=…` for slug disambiguation). Only `draft` submissions can be renamed; non-drafts and concurrent changes return `409`. Success returns `{ success: true, data: { title, updatedAt } }`. Renaming records `draft_title_updated` without changing pinned render inputs or version. Invalid/extra fields return `400`.
- Saved-artwork scene renders use `POST /api/admin/collectibles/{id}/render-spin` and `POST /api/admin/packs/{id}/render-opening`, not a new generic render URL. Both share `lib/saved-artwork-render-route.ts` (`queueSavedArtworkRender`). An optional JSON body supplies a trimmed 1–120 character `title`; omit the body to keep the default title. Bodies over 1 KiB return `413`; malformed JSON or invalid titles return `400`. Optional `expectedTemplateVersion` is a positive-integer query parameter; a changed template returns `409`. A newly queued request returns `202` and an idempotently reused request returns `200`. The server derives collectible name, rarity, team branding, and pack reveal size from the saved target, not client metadata.

## Team short name

- `PUT /api/admin/teams/{teamId}` accepts `nickname`, the short club name the app shows where it uses a short name.
- The value is trimmed and its whitespace collapsed. `null` or a blank value clears it, so clients derive the short name from `name`. Omit `nickname` to leave the stored value unchanged.
- A non-string or a value over 40 characters returns `400`.
- In the admin team editor, **Short name** shows only when you edit an existing team. Its placeholder is the derived name that applies when the field is blank. `POST /api/admin/teams` does not accept `nickname`.

## Error behavior and safeguards

- Unauthorized and forbidden states are explicit and role-driven.
- Invalid payloads and missing resources return typed error responses.
- Ownership and role invariants are protected server-side.
