## Representative non-admin platform routes

- `GET /api/health`
- `GET /api/leaderboard/stream`
- `GET /api/locker-room/stream`
- `POST /api/feed/signals` (authenticated). Opted-in batches persist as `FeedSignal` rows (max 50 events, 64KB, 30 batches/min). Opt-out drops the payload. The response includes `accepted`.
- `POST /api/upload/banner`, `/api/upload/binder-cover`, `/api/upload/locker-media`, `/api/upload/profile`
- `POST /api/cron/sync-trends`
- feature-specific sync routes such as quest/leaderboard synchronization paths
- Apple Wallet: `POST /api/v1/passes/apple-wallet` (authenticated, Node runtime) signs fan ID, club membership, and arena event `.pkpass` files (club membership passes only for an Engage partner club the caller has joined, else `403`); `format: "base64"` returns JSON for native clients.
- App Clips: `GET /api/v1/app-clips/arena/{id}` (public) returns a read-only arena preview for the iOS App Clip, with a weak ETag. Its `team` is the check-in club (the home club for a game event); when `checkInAvailable` is true, signed-in clients check in with a Clerk bearer token on `POST /api/v1/engage/quests/arena-check-in` and `{ "teamId": team.id }`.

## Runtime behavior highlights

- Stream routes deliver incremental updates and require reconnect-aware clients.
- Sync routes refresh derived data used by dashboard and ranking experiences.
- Maintenance scripts reconcile historical inconsistencies without changing primary route contracts.
- Unbuilt `/api/*` paths hit a catch-all that returns JSON `404` with code `NOT_FOUND` instead of the HTML app 404.

## Pass issuance

`POST /api/v1/passes/google-wallet` returns `{ success: true, data: { saveUrl, jwt, passKind, objectId, classId } }` and `Cache-Control: no-store`. The optional JSON body is capped at 4 KiB. An unknown team or game returns `404 NOT_FOUND`; missing or invalid signing configuration returns `503 CONFIGURATION_ERROR`. It requires a Clerk session and returns `404 USER_NOT_PROVISIONED` if the fan has no D-Sports account.

## Widget snapshot

`GET /api/v1/widgets/snapshot` accepts a Clerk session or a `wgt_` bearer scoped to `widgets:snapshot:read`. The snapshot returns `404 USER_NOT_PROVISIONED` if the authenticated fan has no D-Sports account.

- `rankOrPoints` includes Fan Rep, global rank by earned points (nullable), an update timestamp, and a relative leaderboard link.
- `hqLive` selects the latest non-demo live game by start time among the fan’s favorite or followed clubs, or returns `null`. An active card includes club `slug`, home and away scores, raster logos, team colors, period, clock, and nullable `lastPlay` and `squadLabel`. If there is no raster logo, the logo is `null`; colors prefer the team theme color, then the first nonblank gradient color.
- `hqLive.deepLink` remains the relative web locker-room link. `appDeepLink` uses `engagenative://hq/match/<gameId>?slug=<slug>`; the query is omitted if the slug is unavailable.
- `?include=clubs` adds up to six favorite or followed clubs (HQ stars are not follows). Each card includes branding and a non-demo game summary, including its native deep link. The server prioritizes live, then soonest upcoming, then latest final, with no-game cards last (`game: null`). The array is omitted unless requested and is empty if requested with no eligible clubs.

Successful responses vary by `Authorization, Cookie` and are private: `max-age=60` when the returned HQ Live card or an included club game is live, and `max-age=3600` otherwise. The weak `ETag` ignores `updatedAt`. A matching `If-None-Match` returns `304` with no body and with the cache headers preserved; never share the local cache across users.

A widget credential is issued once for an installation and expires after 90 days without use. Snapshot reads using it are limited to 60 per hour per token, including conditional reads. Issuance requires a Clerk session and is limited to 20 per hour per user. Exceeding either limit returns `429`; an unavailable limiter returns `503`. See [the widget API](/api-reference/domains/platform-infra#widget-api) for the token endpoints.

## Android Live Update tone

The Android push payload adds `live_notification.event_updates.semanticTone` without changing the game status or the iOS payload. The first matching rule wins:

| Tone | When the backend sends it |
| --- | --- |
| `final` | End event or terminal game status. |
| `urgent` | Live scoring update, overtime, shootout, or a third-period score gap of at most one when both scores are known. |
| `info` | Other live play. |
| `neutral` | All other states. |

This is a styling hint for Android 17 ProgressStyle. Older clients can ignore it, and clients must handle pushes without the field.

## Script categories in current backend

- backfills (points, onboarding, packs, quests)
- cleanup/deduplication tasks
- repair scripts for ranking/order/state drift
- seed and setup utilities

## Known caveats

- Script execution order matters for some repair workflows.
- Stream routes are bounded by runtime constraints and should be treated as short-lived transport sessions.

## Exclusions

- Privileged admin operations and internal-only maintenance controls are excluded from this non-admin section.
