## Overview

Use this page as the behavior hub for gamification runtime semantics.

Detailed behavior docs:

- Quests: `/repositories/d-sports-api/gamification/quests`
- Points: `/repositories/d-sports-api/gamification/points`
- Leaderboards: `/repositories/d-sports-api/gamification/leaderboards`
- Rewards: `/repositories/d-sports-api/gamification/rewards`
- Achievements: `/repositories/d-sports-api/gamification/achievements`

## Behavior focus areas

- Progress checks and completion gates
- Daily quiz sessions under `/api/v1/engage/quests/*`
- Points write/read consistency
- Leaderboard season-scoped ranking outcomes
- Reward claim/redeem decision paths
- Fan Rep is a separate ledger — see [Fan Rep](/repositories/d-sports-api/fan-rep/index)

`POST /api/v1/engage/quests/arena-check-in` requires both `teamId` and `arenaId`. A claim counts once per team per UTC day, and only while an eligible fixture at the scanned arena is in its check-in window and that team is playing. See the [daily quest contract](/api-reference/domains/gamification#daily-quest-session-contract) for arena IDs, time windows, and errors.

See [authored content locales](/api-reference/domains/gamification#authored-content-locales) for locale selection, response headers, and English fallback on quest, trivia, and achievement reads.

The app-open aggregate (`GET /api/v1/engage/app-open`) labels its response with the negotiated request locale, even if all authored text in `user` and `dailyQuest` falls back to English. Its section errors use the negotiated locale.

## End-to-end quest lifecycle

1. Fetch active quests and eligibility context.
2. Start/advance quest progression through quest routes.
3. Resolve completion and points side effects.
4. Refresh rewards and leaderboard views after mutation events.

## Pass transition scenarios

- User gains or loses **global pass** eligibility.
- User enters/exits **event pass** eligibility windows.
- Quest availability and completion pathways shift based on pass state.

## Cross-team user progression behavior

- Team-scoped quest progression can vary across user team contexts.
- Team/favorites updates can change available quest surfaces.
- Server responses remain source-of-truth for progression state.
