## App architecture

The native app is structured around Expo Router screens, feature-oriented components, shared hooks, and API modules. Screen files are JSX-only shells. State, effects, and handlers live in dedicated hooks.

- Routing: `app/*` with grouped routes for `(tabs)`, `(auth)`, `(onboarding)`, `(admin)`, plus `app/binder`, `app/market`, `app/quests`, `app/settings`, and the engine route `app/(tabs)/locker-room/games/[gameKey]`.
- Feature logic: extracted hooks such as `use-wallet-screen.ts` and `use-shop-screen.ts`.
- Shared contexts: user, collectibles, accessibility, and UI visibility/state controls.
- Styles: dedicated `*.styles.ts` files. Do not put `StyleSheet.create` inside screen files.

## State and context boundaries

- Local/ephemeral UI state lives near feature hooks and components.
- Cross-screen state is managed with Zustand and persisted through MMKV.
- API responses can fall back to `lib/api/cache.ts` (MMKV).
- User/session-sensitive state is coordinated with backend auth and profile sync endpoints.

## API client and retry behavior

- Game Center and locker-room lineups use `lib/api/events-api.ts`, `lib/api/locker-room-api.ts`, and `GET /api/teams/{id}/roster`.
- Game Engine calls use `lib/api/games-engine-api.ts` through `useGamesEngineApi()`, not the shared `useApi()` bag. See [Game Engine client](/repositories/game-engine/client).
- All other network calls route through `lib/api/*` modules.
- Client wrappers handle auth token propagation, error normalization, and retry strategy.
- Quest, Fan Rep, reward, and team flows should consume backend eligibility as source of truth.

## Auth and deep-link entry

- Clerk (`@clerk/expo`) owns the session after login.
- Login supports Google OAuth, Apple Sign In, email/password, and MFA (TOTP, SMS, or email code).
- Mobile OAuth can land a 128-char hex token in the URL fragment. `+native-intent.tsx` and `captureDeepLinkUrl` parse it, `takePendingMobileSessionToken()` stashes it in memory (not MMKV), and `consumePendingMobileSessionToken` redeems it at `POST /api/mobile/exchange`.
- Android App Links cover `api.d-sports.org` mobile callbacks and `app.d-sports.org` paths (`/locker-room`, `/profile`, `/market`, `/quests`, `/binder`, `/leaderboard`, `/rate`). iOS also claims `applinks:app.d-sports.org`.

## Native configuration and iOS capabilities

`app.json` owns the base Expo configuration. `app.config.ts` applies environment-dependent overrides, including associated domains derived from the API and app web hosts. PR #1398 added the following native capabilities; plugin, entitlement, privacy-manifest, and icon changes require a new binary rather than an OTA alone.

- **Passkey domain association:** iOS declares both `applinks:` and `webcredentials:` for the API and app hosts, deduplicating matching hosts. Production defaults are `api.d-sports.org` and `app.d-sports.org`. Webcredentials enables passkey/Keychain AutoFill domain association; it does not replace the server's AASA file or add a new authentication flow by itself.
- **Privacy manifest:** `ios.privacyManifests` declares `NSPrivacyAccessedAPICategoryUserDefaults` reasons `CA92.1` and `1C8F.1`. Expo generates `PrivacyInfo.xcprivacy` at prebuild. This is a required-reason API declaration, not a complete data-collection disclosure.
- **Shared App Group:** OneSignal and `expo-widgets` use `group.com.dsports.wallet.beta.dengage`. Keep extension signing, plugin configuration, and shared UserDefaults access aligned.
- **Icon Composer:** `ios.icon` still points to the primary `assets/app.icon`, containing `icon.json` and `Assets/`. #1403 adds separate PNG alternate icons without replacing the primary bundle. Android adaptive icons and the web favicon remain separately configured.
- **Picture-in-picture:** the `expo-video` plugin sets `supportsPictureInPicture: true`, enabling iOS background audio and Android PiP support. Opted-in video views still control playback behavior.
- **Calendar:** the `expo-calendar` plugin requests write-only calendar access with a usage description and disables reminders permission. The client opens the native event editor through `expo-calendar/legacy`; it does not read calendars or the Reminders database.

For source ownership and focused regression tests, see the native repository's [maintained capabilities guide](https://github.com/D-Sports-Ecosystem/d-sports-engage-native/blob/main/docs/ios-native-capabilities.md).

The roster remains four options: **D-Sports** (`default`, native `null`), **D-Sports Gold** (`dsports-gold` / `AppIconGold`), **HC Sierre** (`hc-sierre` / `AppIconHCSierre`, team slug `hc-sierre`), and **Milano HC** (`milano-hc` / `AppIconMilanoHC`, team slug `milano-hc`). Later JS-only copy/picker changes need a compatible binary containing the named icons. Tests in `plugins/__tests__/withAlternateAppIcons.test.ts`, `modules/expo-alternate-icons/__tests__/expo-alternate-icons.test.ts`, and `features/settings/screen/__tests__/app-icon-screen.test.tsx` cover generation/build settings, invalid configuration, bridge fallbacks/delegation, and HC Sierre selection/reset, Milano HC errors, skipped selection, unknown-name fallback, and retained Gold lookup. It normalizes blank/null to default, skips an already-exclusive target, and rejects unknown/missing targets or missing support/context. This is not a transactional switch with rollback or a launcher-compatibility probe; no new runtime permission is added.

Static `android.app.shortcuts` metadata is copied onto every launcher alias. `withAndroidPlatformCapabilities.js` also applies it to existing aliases if plugin execution order is reversed. This preserves declarations, not proof that every launcher preserves long-press or pinned shortcut behavior. The PR adds no dynamic/pinned shortcut rebinding. Supported Android 13+ launchers can tint/mask the monochrome layer when the system **Themed icons** setting is enabled; the picker neither toggles that setting nor forces launcher refresh/restart. Normal adaptive/legacy artwork remains the non-themed path. See [Android launcher behavior](/repositories/d-sports-engage-native/feature-mapping#android-launcher-icons).

Compatible JS-only picker/copy updates need those native resources already installed. ## Share Extension configuration

PR #1400 registers `plugins/withIosShareExtension.js` in `app.json`. Prebuild generates the iOS 17+ `DSportsShareExtension` target (`com.dsports.wallet.beta.ShareExtension`) from `plugins/share-extension/ShareViewController.swift`, with a share-services Info.plist and App Group entitlements. The plugin adds EAS `appExtensions` metadata without dropping other extensions. It merges `com.apple.security.application-groups` into the host entitlements and gives both targets `group.com.dsports.wallet.beta.dengage`. It writes `EngageShareAppGroup` in the host and extension Info.plists, plus `EngageShareUrlScheme` (`engagenative`) in the extension. Provision both targets for that App Group. PR #1442 points the target's product reference at the `BUILT_PRODUCTS_DIR` `DSportsShareExtension.appex` file and embeds that reference through the main app target's **Embed Foundation Extensions** copy phase. The plugin reuses that phase when another extension, such as `expo-widgets`, already created it, and repeated runs add no duplicate entry. This fixes Release archive failures caused by a duplicate group-relative `.appex` reference.

Activation rules advertise four images, one web URL, and plain text. The extension writes a versioned manifest and converted photos under App Group `share-handoffs/{id}/`. Only the ID enters the `engagenative://share-inbox?id={id}` URL. The local iOS Expo module `modules/expo-share-handoff/` stages photos in app temporary storage before consuming the shared folder. Staging failures preserve the original handoff; no automatic retry is added. Payload validation enforces a 24-hour TTL, schema, safe IDs, local image URIs, and a four-image cap. Intake sweeps stale shared and temporary directories; the extension also sweeps stale shared directories.

`useDeepLinkBootstrap` captures this hostname-only route for cold/warm entry and restores it after the authenticated/onboarded `inApp` gate opens. `RootAuthStack` protects `/share-inbox` with that gate. `useShareInbox` queues the validated draft in memory, then replaces the route with Locker Room. `useShareDraftIntake` consumes it once and suppresses server-draft restoration for that composer opening. See [draft behavior](/repositories/d-sports-engage-native/feature-mapping#share-extension-drafts) for supported content and failure limits.

The extension target, entitlements, and native bridge require a new binary, not OTA alone. `plugins/__tests__/withIosShareExtension.test.ts` covers registration, activation rules, template presence, App Group merging, EAS metadata, the single `BUILT_PRODUCTS_DIR` `.appex` embed, and reuse of an existing **Embed Foundation Extensions** phase. `lib/locker-room/__tests__/share-handoff.test.ts` covers validation, TTL, empty/error cases, caps, formatting, queueing, and restore suppression. These tests do not run a Release archive or prove signed extension discovery, Swift photo staging, or device/auth handoff.

## Home Screen Quick Actions configuration

PR #1406 adds the local iOS module `modules/expo-quick-actions/`. Its `expo-module.config.json` registers `ExpoQuickActionsModule` and `ExpoQuickActionsAppDelegateSubscriber`. It uses UIKit `UIApplicationShortcutItem`, not a new plugin, static `UIApplicationShortcutItems` Info.plist array, App Group, entitlement, or extension target. `app.json`, `app.config.ts`, and the root `package.json` are unchanged. The module podspec declares iOS 16.4; these shortcuts are separate from iOS 18 Control Center controls and Siri App Intents.

`RootAuthStack` mounts `useQuickActionsBootstrap`. On iOS mount and app-locale changes, it registers the four dynamic items from `lib/quick-actions/catalog.ts` with English, French, or Italian titles and SF Symbols. The native setter considers only the first four items, skips empty IDs/titles, and replaces the dynamic list. No static fallback exists before app-side registration. Android, web, Expo Go, and older binaries without the module no-op. Registration failures return `false` and log a warning, rather than proving OS menu presentation.

Expo's scene delegate forwards cold-launch shortcut connection options to the app-delegate subscriber; non-scene launch options provide a fallback. Warm taps arrive through `performActionFor`. The native store buffers the latest tap until observation starts and drains it once; the hook also calls `consumeInitialAction`. `routeQuickAction` resolves known IDs from the catalog rather than trusting event `params.href`. It calls `router.navigate` when `inApp` is true. Otherwise it force-stashes the target in the in-memory pending-href helper, and `useDeepLinkBootstrap` restores it after authentication/onboarding. This is not a durable multi-action queue.

The module and subscriber require a new binary. Once the installed binary contains them, JS-only catalog, translation, or routing changes can use a compatible OTA; dynamic items refresh when the bootstrap runs. `lib/quick-actions/__tests__/quick-actions.test.ts` covers catalog/order/routes/symbols, localization, registration and unavailable/error cases, warm navigation, post-auth/forced restoration, and unknown/empty IDs. It does not verify Swift buffering, native launch delivery, or OS menu discovery. See [Quick Actions behavior](/repositories/d-sports-engage-native/feature-mapping#home-screen-quick-actions) for each destination.

## Android AppSearch and AppFunctions integration

PR #1423 adds Android counterparts to [iOS Spotlight](#core-spotlight-and-handoff-integration) and [App Intents](#tier-2-native-integration).
It does not implement Android Handoff.
`AndroidCapabilitiesHost.android.tsx` calls `hooks/use-android-search-sync.android.ts` with the authenticated/onboarded `inApp` gate.
The hook reuses `lib/spotlight/` mappers for `user.favoriteTeams`, active-wallet binder summaries, and owned collectibles.
It refreshes binders on mutation and foregrounding, and clears stale binder rows on wallet changes or fetch failure.
No new API route or contract is added.

`lib/android/search-index.android.ts` maps the shared `engage:<kind>:<id>` identifiers to `engagenative://` routes.
The deduplicated batch caps at 250 entries, prioritizing teams, binders, then cards.
Writes debounce by 1.5 seconds, skip unchanged MMKV hashes, and remove stale IDs.
Partial native writes clear the hash for a later retry while retaining potentially indexed IDs for pruning.
The hook persists the last synced user ID across remounts.
Sign-out, account deletion, settled signed-out startup, and account switching request index/cache cleanup through the hook and `features/user/useUserAuthActions.ts`.
JS generations and serialized native mutations with a clear epoch guard obsolete writes.
Cleanup errors remain possible; do not treat the request as guaranteed synchronous OS deletion.

Native sources live under `modules/expo-android-capabilities/android/src/main/java/expo/modules/androidcapabilities/`:

| Source | Responsibility |
| --- | --- |
| `AndroidAppSearch.kt` | Database `dsports_engage_search`; schemas `DSportsTeam`, `DSportsCard`, `DSportsBinder`; namespaces `teams`, `cards`, `binders`. Stores title, subtitle, keywords, deep link, domain identifier, entity type, and optional thumbnail URL. |
| `ExpoAndroidCapabilitiesModule.kt` | Index/delete/clear/search operations, cache methods, availability gates, and AppSearch session closure on module destroy. |
| `appfunctions/BaseDSportsAppFunctionService.kt` | API 36+ declarations for `getLiveScore`, `getFanRep`, `openArenaQr`, and `searchCollectibles`. |
| `appfunctions/DSportsAppFunctionModels.kt` | Serializable results with immutable, package-scoped launch `PendingIntent`s. |
| `appfunctions/AndroidAppFunctionsCache.kt` | Private SharedPreferences snapshots for Fan Rep and one HQ score, readable without starting React Native JS. |

AppSearch is available from API 26 with the native module.
API 31+ prefers `PlatformStorage` and marks the schemas displayable by the system.
API 26–30 or platform-storage failure uses `LocalStorage`, which is not system-search delivery.
Title, subtitle, and keywords use prefix indexing; domain and entity type use exact terms.
Non-Android wrappers and missing modules safely no-op.
AppFunctions availability reports API 36+ with the module, not actual assistant/provider eligibility.

The module's `android/build.gradle` adds AppSearch core/local/platform storage 1.1.0, AppFunctions/runtime compiler 1.0.0, and concurrent-futures-ktx 1.2.0.
It applies KSP.
`plugins/withAndroidPlatformCapabilities.js` injects KSP classpath `2.1.20-2.0.1` for metadata generation.
The module manifest registers generated `DSportsAppFunctionService` as exported with `android.permission.BIND_APP_FUNCTION_SERVICE` protection.
It references generated schema/service metadata and `res/xml/app_metadata.xml`.

PR #1446 fixes Google Play rejecting the AAB's incomplete AppFunctions metadata.
`modules/expo-android-capabilities/android/src/main/res/xml/app_metadata.xml` declares `app:displayDescription="@string/appfunctions_display_description"` and `app:instructions` under `xmlns:app="http://schemas.android.com/apk/res-auto"`.
It replaces the former `appfn:instructions` with res-auto instructions and a legacy `appfn:description` under `xmlns:appfn="http://schemas.android.com/apk/androidx.appfunctions"`.
Both instruction/description attributes carry the same operational guidance for the four functions, read-only on-device caches, and signed-out personal-data limits.
These declarations describe behavior; they do not add runtime enforcement.
The localizable `appfunctions_display_description` resource lives in `modules/expo-android-capabilities/android/src/main/res/values/strings.xml`.
Its default English value is “Check live game scores, view your Fan Rep, search your collectible cards, and open the Arena QR scanner in D-Sports Engage.”
PR #1446 adds no locale-specific `values-*` translations, manifest changes, ProGuard changes, or tests.
Shipping this XML/string resource fix requires a rebuilt Android binary/AAB, not an OTA update.

ProGuard keeps the module's `appfunctions.**`, `androidx.appfunctions.**`, and `androidx.appsearch.**` classes.
These native dependencies, Kotlin, Gradle, service, and metadata changes need a rebuilt Android binary.
Only later compatible JS changes can use OTA.

Focused tests are `lib/android/__tests__/search-index.test.ts`, `lib/android/__tests__/app-functions.test.ts`, and `plugins/__tests__/withAndroidPlatformCapabilities.test.ts`.
They cover mapping, empty/invalid items, reconciliation, clearing, partial writes, availability delegation, snapshot normalization, and KSP injection/source declarations.
They do not prove Kotlin compilation, generated-service execution, system/assistant discovery, or device search and cleanup behavior.
See [function behavior](/repositories/d-sports-engage-native/feature-mapping#android-appsearch-and-appfunctions) for cache limits and launch semantics.

## Android NFC configuration

PR #1425 adds `modules/expo-android-nfc/` and registers `plugins/withAndroidNfc.js` in `app.json`.

`ExpoAndroidNfcModule.kt`, `DsportsNfcHceService.kt`, and `NdefUrlCodec.kt` live under `modules/expo-android-nfc/android/src/main/java/expo/modules/androidnfc/`.
The service emulates a read-only NFC Forum Type 4 Tag containing one NDEF URI record.
The reader accepts physical NDEF tags and peer Android HCE over IsoDep.
This is neither Android Beam nor a physical-tag writer.
The module depends on `androidx.core:core-ktx:1.15.0`.
Its consumer ProGuard rules keep the Expo module and HCE service.

The plugin adds `android.permission.NFC`.
It declares `android.hardware.nfc` and `android.hardware.nfc.hce` with `required="false"`.
The exported HCE service requires `android.permission.BIND_NFC_SERVICE`.
Generated `res/xml/nfc_aid_list.xml` requires device unlock and uses category `other`.
It registers the standard Type 4 NDEF AID `D2760000850101` and custom AID `F04453504F52545301`.
There is no user-facing rollout flag or Android 16/17 API-level gate in this bridge.

`NDEF_DISCOVERED` filters accept HTTPS `/clip/arena`, `/profile`, and `/binder` prefixes on `extra.appWebHost`, defaulting to `app.d-sports.org`.
The plugin writes that host to `com.dsports.engage.NFC_ALLOWED_HOST` metadata.
Native and JS validators accept production/configured hosts and reject non-HTTPS or unsupported paths.
The native codec rejects `..` and URLs longer than 512 characters.
`lib/android/nfc-url.ts` adds route and identifier validation.
Manifest prefix matching alone is not validation.

`AndroidCapabilitiesHost.android.tsx` mounts `hooks/use-android-nfc-host.android.ts` for cold/warm intents and live reader events.
The hook queues the latest link until the authenticated/onboarded `inApp` gate opens.
It suppresses identical URLs for three seconds.
The share sheet refreshes status and rearms its selected mode on resume.
Closing it stops sharing and reading.
Native background/destroy callbacks also stop both modes and clear the in-memory share URL.
