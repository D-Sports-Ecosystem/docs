## App architecture

The native app is structured around Expo Router screens, feature-oriented components, shared hooks, and API modules. Screen files are JSX-only shells. State, effects, and handlers live in dedicated hooks.

- Routing: `app/*` with grouped routes for `(tabs)`, `(auth)`, `(onboarding)`, `(admin)`, plus `app/binder`, `app/market`, `app/quests`, `app/settings`, and the engine route `app/(tabs)/locker-room/games/[gameKey]`.
- Feature logic: extracted hooks such as `use-wallet-screen.ts` and `use-shop-screen.ts`.
- Shared contexts: user, collectibles, accessibility, and UI visibility/state controls.
- Styles: dedicated `*.styles.ts` files. Do not put `StyleSheet.create` inside screen files.

## State and context boundaries

- Local/ephemeral UI state lives near feature hooks and components.
- Cross-screen state is managed with Zustand and persisted through MMKV.
- API responses can fall back to `lib/api/cache.ts` (MMKV).
- User/session-sensitive state is coordinated with backend auth and profile sync endpoints.

## API client and retry behavior

- Game Center and locker-room lineups use `lib/api/events-api.ts`, `lib/api/locker-room-api.ts`, and `GET /api/teams/{id}/roster`.
- Game Engine calls use `lib/api/games-engine-api.ts` through `useGamesEngineApi()`, not the shared `useApi()` bag. See [Game Engine client](/repositories/game-engine/client).
- All other network calls route through `lib/api/*` modules.
- Client wrappers handle auth token propagation, error normalization, and retry strategy.
- Quest, Fan Rep, reward, and team flows should consume backend eligibility as source of truth.

## Auth and deep-link entry

- Clerk (`@clerk/expo`) owns the session after login.
- Login supports Google OAuth, Apple Sign In, email/password, and MFA (TOTP, SMS, or email code).
- Mobile OAuth can land a 128-char hex token in the URL fragment. `+native-intent.tsx` and `captureDeepLinkUrl` parse it, `takePendingMobileSessionToken()` stashes it in memory (not MMKV), and `consumePendingMobileSessionToken` redeems it at `POST /api/mobile/exchange`.
- Android App Links cover `api.d-sports.org` mobile callbacks and `app.d-sports.org` paths (`/locker-room`, `/profile`, `/market`, `/quests`, `/binder`, `/leaderboard`, `/rate`). iOS also claims `applinks:app.d-sports.org`.

## Native configuration and iOS capabilities

`app.json` owns the base Expo configuration. `app.config.ts` applies environment-dependent overrides, including associated domains derived from the API and app web hosts. PR #1398 added the following native capabilities; plugin, entitlement, privacy-manifest, and icon changes require a new binary rather than an OTA alone.

- **Passkey domain association:** iOS declares both `applinks:` and `webcredentials:` for the API and app hosts, deduplicating matching hosts. Production defaults are `api.d-sports.org` and `app.d-sports.org`. Webcredentials enables passkey/Keychain AutoFill domain association; it does not replace the server's AASA file or add a new authentication flow by itself.
- **Privacy manifest:** `ios.privacyManifests` declares `NSPrivacyAccessedAPICategoryUserDefaults` reasons `CA92.1` and `1C8F.1`. Expo generates `PrivacyInfo.xcprivacy` at prebuild. This is a required-reason API declaration, not a complete data-collection disclosure.
- **Shared App Group:** OneSignal and `expo-widgets` use `group.com.dsports.wallet.beta.dengage`. Keep extension signing, plugin configuration, and shared UserDefaults access aligned.
- **Icon Composer:** `ios.icon` still points to the primary `assets/app.icon`, containing `icon.json` and `Assets/`. #1403 adds separate PNG alternate icons without replacing the primary bundle. Android adaptive icons and the web favicon remain separately configured.
- **Picture-in-picture:** the `expo-video` plugin sets `supportsPictureInPicture: true`, enabling iOS background audio and Android PiP support. Opted-in video views still control playback behavior.
- **Calendar:** the `expo-calendar` plugin requests write-only calendar access with a usage description and disables reminders permission. The client opens the native event editor through `expo-calendar/legacy`; it does not read calendars or the Reminders database.

For source ownership and focused regression tests, see the native repository's [maintained capabilities guide](https://github.com/D-Sports-Ecosystem/d-sports-engage-native/blob/main/docs/ios-native-capabilities.md).

## Alternate app icon configuration

`app.json` registers `plugins/withAlternateAppIcons.js` (introduced in #1403; roster updated in #1411). It maps `AppIconGold`, `AppIconHCSierre`, and `AppIconMilanoHC` to `assets/app-icons/dsports-gold.png`, `hc-sierre.png`, and `milano-hc.png` respectively (all in `assets/app-icons/`). Prebuild validates names, nonempty paths, and source existence, then creates universal 1024×1024 `.appiconset` entries under the app's `Images.xcassets`. The plugin enables `ASSETCATALOG_COMPILER_INCLUDE_ALL_APPICON_ASSETS` and sets `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES` on app configurations with a primary icon setting, skipping `SKIP_INSTALL=YES`. It preserves the primary icon setting; Xcode compiles the alternate declarations alongside the existing `.icon` primary.

The local Apple-only module `modules/expo-alternate-icons/` wraps UIKit support checks, current-name reads, and main-queue `setAlternateIconName`. No new extension, App Group, or entitlement is added. `app.config.ts` and the root `package.json` are unchanged. The picker catalog is `constants/app-icons.constants.ts`; its primary preview is `assets/images/icon-square.png`, not a new primary native icon source. `useAppIconScreen` coordinates selection and errors, while in-process subscriptions update the Appearance row. This is native device state, not a backend preference.

The roster remains four options: **D-Sports** (`default`, native `null`), **D-Sports Gold** (`dsports-gold` / `AppIconGold`), **HC Sierre** (`hc-sierre` / `AppIconHCSierre`, team slug `hc-sierre`), and **Milano HC** (`milano-hc` / `AppIconMilanoHC`, team slug `milano-hc`). PR #1411 removes only the London Knights/Oshawa Generals assets and config/catalog entries; Gold remains. The team artwork uses D-Sports branding in club-themed colors. Team labels are `brandName` values; default/Gold labels and descriptions live in `locales/{en,fr,it}/settings.json`.

There is no removed-name migration in the hook or native bridge. An unknown native name falls back through `findAppIconOption` for the Appearance summary only; the picker compares raw names and marks no option selected. Selecting primary explicitly invokes the native setter with `null`. Source tests do not verify how iOS handles removed artwork during a binary upgrade.

Build a new binary for the native module, asset catalogs, and Xcode settings. OTA cannot add or replace compiled app-icon artwork. Later JS-only copy/picker changes need a compatible binary containing the named icons. Tests in `plugins/__tests__/withAlternateAppIcons.test.ts`, `modules/expo-alternate-icons/__tests__/expo-alternate-icons.test.ts`, and `features/settings/screen/__tests__/app-icon-screen.test.tsx` cover generation/build settings, invalid configuration, bridge fallbacks/delegation, and HC Sierre selection/reset, Milano HC errors, skipped selection, unknown-name fallback, and retained Gold lookup. They do not specifically simulate an upgrade from a removed icon. They do not establish real Xcode compilation, OS switching, or device rendering. See [icon selection behavior](/repositories/d-sports-engage-native/feature-mapping#alternate-app-icons).

## Share Extension configuration

PR #1400 registers `plugins/withIosShareExtension.js` in `app.json`. Prebuild generates the iOS 17+ `DSportsShareExtension` target (`com.dsports.wallet.beta.ShareExtension`) from `plugins/share-extension/ShareViewController.swift`, with a share-services Info.plist and App Group entitlements. The plugin adds EAS `appExtensions` metadata without dropping other extensions. It merges `com.apple.security.application-groups` into the host entitlements and gives both targets `group.com.dsports.wallet.beta.dengage`. It writes `EngageShareAppGroup` in the host and extension Info.plists, plus `EngageShareUrlScheme` (`engagenative`) in the extension. Provision both targets for that App Group.

Activation rules advertise four images, one web URL, and plain text. The extension writes a versioned manifest and converted photos under App Group `share-handoffs/{id}/`. Only the ID enters the `engagenative://share-inbox?id={id}` URL. The local iOS Expo module `modules/expo-share-handoff/` stages photos in app temporary storage before consuming the shared folder. Staging failures preserve the original handoff; no automatic retry is added. Payload validation enforces a 24-hour TTL, schema, safe IDs, local image URIs, and a four-image cap. Intake sweeps stale shared and temporary directories; the extension also sweeps stale shared directories.

`useDeepLinkBootstrap` captures this hostname-only route for cold/warm entry and restores it after the authenticated/onboarded `inApp` gate opens. `RootAuthStack` protects `/share-inbox` with that gate. `useShareInbox` queues the validated draft in memory, then replaces the route with Locker Room. `useShareDraftIntake` consumes it once and suppresses server-draft restoration for that composer opening. See [draft behavior](/repositories/d-sports-engage-native/feature-mapping#share-extension-drafts) for supported content and failure limits.

The extension target, entitlements, and native bridge require a new binary, not OTA alone. `plugins/__tests__/withIosShareExtension.test.ts` covers registration, activation rules, template presence, App Group merging, and EAS metadata. `lib/locker-room/__tests__/share-handoff.test.ts` covers validation, TTL, empty/error cases, caps, formatting, queueing, and restore suppression. These tests do not prove signed extension discovery, Swift photo staging, or device/auth handoff.

## Tier 2 native integration

PR #1397 adds app-target Swift sources under `app-intents/`, not a separate shortcut extension. `app.json` registers `expo-app-intents` and `experiments.inlineModules.watchedDirectories: ["app-intents"]`; `package.json` includes the native package. `AppIntentsSetup.swift` refreshes shortcut parameters. `AppIntentsHost`, mounted by `RootAuthStack`, processes invocations only after the authenticated/onboarded `inApp` route gate opens. The resolver lives in `lib/ios/app-intents.ts`.

The iOS tab layout enables `minimizeBehavior="onScrollDown"` and conditionally mounts `LiveGameBottomAccessory` for a live snapshot. `services/live-game-accessory-store.ts` holds the in-memory state, synchronized by Live Activity snapshot writes/clears and restored from MMKV by the intent host. This iOS 26+ tab accessory is separate from ActivityKit and WidgetKit.

Presentation stays in route layouts: `app/hq/_layout.tsx` uses iOS `formSheet` for `game/[gameId]` with detents `[0.65, 1.0]`; the locker-room layout uses `[0.85, 1.0]` for `wheel-spin` and `player-guess`. Both configure a system grabber and 24-point corner radius. Non-iOS keeps modal presentation, and engine `games/[gameKey]` remains a pushed screen. The HQ summary keeps its iOS top bar inside the scroll view and omits the duplicate custom grabber.

For iOS 27 resizable-window compatibility, `lib/ios/resizable-window.ts` uses a finite, positive shortest-side threshold of 600 dp, not OS-version or model detection. The media viewer skips orientation capture/lock/unlock on those iOS windows and on web. This is not an app-wide orientation rewrite or a new window target. Selected card previews use Expo Router links; their share helper defaults to the canonical app origin rather than an environment-derived host.

## Home Screen Quick Actions configuration

PR #1406 adds the local iOS module `modules/expo-quick-actions/`. Its `expo-module.config.json` registers `ExpoQuickActionsModule` and `ExpoQuickActionsAppDelegateSubscriber`. It uses UIKit `UIApplicationShortcutItem`, not a new plugin, static `UIApplicationShortcutItems` Info.plist array, App Group, entitlement, or extension target. `app.json`, `app.config.ts`, and the root `package.json` are unchanged. The module podspec declares iOS 16.4; these shortcuts are separate from iOS 18 Control Center controls and Siri App Intents.

`RootAuthStack` mounts `useQuickActionsBootstrap`. On iOS mount and app-locale changes, it registers the four dynamic items from `lib/quick-actions/catalog.ts` with English, French, or Italian titles and SF Symbols. The native setter considers only the first four items, skips empty IDs/titles, and replaces the dynamic list. No static fallback exists before app-side registration. Android, web, Expo Go, and older binaries without the module no-op. Registration failures return `false` and log a warning, rather than proving OS menu presentation.

Expo's scene delegate forwards cold-launch shortcut connection options to the app-delegate subscriber; non-scene launch options provide a fallback. Warm taps arrive through `performActionFor`. The native store buffers the latest tap until observation starts and drains it once; the hook also calls `consumeInitialAction`. `routeQuickAction` resolves known IDs from the catalog rather than trusting event `params.href`. It calls `router.navigate` when `inApp` is true. Otherwise it force-stashes the target in the in-memory pending-href helper, and `useDeepLinkBootstrap` restores it after authentication/onboarding. This is not a durable multi-action queue.

The module and subscriber require a new binary. Once the installed binary contains them, JS-only catalog, translation, or routing changes can use a compatible OTA; dynamic items refresh when the bootstrap runs. `lib/quick-actions/__tests__/quick-actions.test.ts` covers catalog/order/routes/symbols, localization, registration and unavailable/error cases, warm navigation, post-auth/forced restoration, and unknown/empty IDs. It does not verify Swift buffering, native launch delivery, or OS menu discovery. See [Quick Actions behavior](/repositories/d-sports-engage-native/feature-mapping#home-screen-quick-actions) for each destination.

## Core Spotlight and Handoff integration

PR #1399 adds the local iOS module `modules/expo-spotlight-handoff/` and registers `plugins/withSpotlightHandoff.js` in `app.json`. The plugin merges `com.dsports.engage.viewTeam`, `viewBinder`, `viewCard`, and `viewPost` into `NSUserActivityTypes` without removing other declarations. The module implements Core Spotlight operations and `NSUserActivity` continuation; Android, web, and missing-module binaries no-op.

`SpotlightSyncBootstrap` owns indexing and continuation routing. `lib/spotlight/` builds a deduplicated batch capped at 250 entries, prioritizing teams, binders, then cards. It debounces updates by 1.5 seconds, persists the last hash/identifiers in MMKV, skips unchanged batches, and removes stale identifiers. `hooks/use-handoff-activity.ts` publishes a focused screen activity using the configured app web origin and clears it on blur. Native cold-start continuation buffering and the authenticated in-app gate prevent routing before protected routes become available.

The App Intents package/inline Swift sources and Spotlight module/Info.plist declarations require a new native build; an OTA alone cannot install them. The source capabilities guide lists focused helper, store, Spotlight, and plugin tests. Unit coverage does not establish Siri, Spotlight/Handoff delivery, or native UI rendering on a device.

## App Clip configuration

`app.json` registers `plugins/withIosAppClip.js`. Prebuild copies `plugins/app-clip/*.swift` into **DSportsAppClip**, embeds the target through **Embed App Clips**, and adds EAS `appExtensions` signing metadata while preserving sibling extensions. The target uses the parent bundle ID plus `.Clip` (`com.dsports.wallet.beta.Clip`). It is a pure-SwiftUI iOS 17.0+ app with no CocoaPods or React Native dependencies. The root `package.json` does not change. `scripts/sync-ios-extension-versions.js` synchronizes its version/build number.

The clip declares the parent-application identifier, App Group `group.com.dsports.wallet.beta.dengage`, and `appclips:app.d-sports.org` entitlements. The plugin preserves the parent's App Groups. `app.json` and `app.config.ts` add the app web host's `appclips:` association; the plugin reads `extra.appWebHost` and `extra.apiOrigin`, defaulting to production. Generated Info.plist metadata includes the API origin, App Group, and App Store ID `6755374760`. `NSAppClip` requests neither location confirmation nor ephemeral notifications. Provisioning, AASA, and App Store Connect invocation experiences remain required; prebuild does not configure the server or store.

The canonical invocation is `https://app.d-sports.org/clip/arena/<id>`. `DSportsAppClipApp.swift` handles browsing-web activity, open URLs, and Xcode's `_XCAppClipURL`. The clip parser also accepts `/clip/<id>` and `arenaId`/`id` query fallbacks, with 1–128-character alphanumeric/underscore/hyphen IDs. The API contract and AASA behavior live in [Platform and infrastructure API](/api-reference/domains/platform-infra) and [Platform behavior](/repositories/d-sports-api/platform-infra/behavior); this page does not redefine them.

`ArenaClipService` writes one timestamped JSON payload to App Group UserDefaults key `engage.appClipHandoff.v1`. The full app's local `modules/expo-app-clip-handoff/` exposes peek/consume/clear operations. `RootAuthStack` mounts `useAppClipHandoff(inApp)`, which peeks only after authentication/onboarding and clears after validation/routing or successful/already-claimed check-in. `app/+native-intent.tsx` separately intercepts installed-app clip links for post-auth preview resolution. See [App Clip behavior](/repositories/d-sports-engage-native/feature-mapping#app-clip).

The target, entitlements, SwiftUI UI, and bridge require a rebuilt signed binary; OTA cannot install or update the clip. Its dependency-free target avoids embedding a JavaScript bundle, but there is no byte-size gate or verified archive-size result. Measure the archived clip against Apple's applicable invocation/distribution size limits before release. Focused tests are `plugins/__tests__/withIosAppClip.test.ts` (registration, source presence, bundle ID, entitlements/plist, EAS idempotence/preservation) and `features/app-clip-handoff/__tests__/handoff-parser.test.ts` (payload validation/expiry, routes, URL scoping, pending-ID queue). They do not validate SwiftUI, signing, invocation discovery, SKOverlay, install-time App Group transfer, auth/check-in effects, or archive size.

## Wallet signing

- Custodial wallets sign on the server via `POST /api/wallets/{address}/sign-transaction`.
- The client PIN-gates the flow. Do not sign with a locally exported private key for custodial sends.
- `POST /api/wallets/private-key` is deprecated on the API.

## Platform-specific behavior

- iOS/Android platform differences are handled in native-specific components and runtime checks.
- iPad and tablets are supported (`supportsTablet`). Orientation-aware layouts exist for tablets and foldables. Web-target support exists but mobile behavior is primary.
- The app requires an Expo **dev client**. Expo Go cannot load MMKV, RevenueCat, or Filament.
- Haptics, modal controls, and animation handling are implemented with platform-safe fallbacks.
