## Feature parity with backend/PWA

`d-sports-engage-native` (1.25.9) targets high parity with `d-sports-api` feature behavior while optimizing for mobile UX patterns.

## Wallet and pack opening

- Wallet screens consume balances, token data, and PIN-gated custodial flows from backend APIs.
- Sends use server-side `sign-transaction`, not on-device private-key signing.
- Pack browsing, purchase, and open flows use backend-driven states and inventory refresh behavior. Start a pack purchase with `POST /api/packs/{id}/purchase`. Do not call `PUT` on that path (`410 GONE`). Confirm crypto checkout with `POST /api/checkout/crypto/verify`.
- Odds-disclosure surfaces read backend-provided probability payloads.

## Native review requests

Shop and wallet pack reveals call `lib/store-review.ts` after a Rare, Epic, Legendary, or Mythic pull. The helper uses `expo-store-review` on iOS and Android and skips web or unavailable APIs. With MMKV storage available, requests are limited to once per installed app version and at least 90 days apart. The OS decides whether to display the review sheet; a request does not guarantee presentation. Game-win and quest-claim moment names exist in the helper type but are not wired triggers. This flow is separate from the app-update prompt.

## Binder and market

- `app/binder` is the digital binder inventory and transfer surface. It talks to `/api/binders*`.
- Binder PIN is not the wallet PIN. Native must store the short-lived verify-pin token and send `x-binder-pin-token` on binder reads.
- You browse packs on `market/packs` and trading on `market/trading` so one tab does not lose the other. Listings go through `/api/v1/marketplace/*` (in generated OpenAPI). `listings/mine` still works; `me/listings` is the live path.
- Card history uses public `GET /api/v1/cards/{id}/provenance`.

## Quest, Fan Rep, rewards, and pass surfaces

- Quest UI supports team-aware progression and pass-gated eligibility.
- Daily quiz sessions use `/api/v1/engage/quests/*`.
- Fan Rep screens read `/api/v1/engage/rep/breakdown` and `/api/v1/engage/rep/ledger`, including `dsportsDirect` ledger rows.
- Reward states and claim flows follow backend quest/reward APIs.
- Global pass and event pass effects are reflected in native quest visibility/completion UX.

## Games

- The games surface joins `GET /api/games/catalog` with `GET /api/v1/engage/games/catalog`. See [Game Engine](/repositories/game-engine/index).
- Legacy keys (daily spin, guess-the-player) still drop when unknown. Engine keys stay visible as **Update required** or **Not in this build**.
- Shipped engine games on `/(tabs)/locker-room/games/{key}`: `daily-pickem`, `daily-trivia`, `prize-wheel-spin`, `guess-the-player`, `daily-lineup`, `card-trivia`, `login-streak-scratcher`, `deflection`, `iron-trap`, `deke-daily`, `faceoff-frenzy`, `sauce-pass`, `empty-net`, `air-hockey`, `locker-singularity`.
- `locker-singularity` uses the idle ledger (`/api/v1/engage/games/locker-singularity/ledger`), not session/action/complete. Send `X-Client-Version` and a client-held UUID `idempotencyKey` on mutations. The client sends tap counts, never buzz amounts.
- How-to-Play walkthroughs stay local. They must not call session/action/complete.
- Game Center uses `/api/events/*` for hero, lineup, player-stats, top-performer, win-probability, chat, presence, ratings, Broadcast discovery, and Live Activity. Ratings submit through `POST /api/events/{gameId}/ratings`.

## Team and leaderboard integration

- Teams and leagues metadata are consumed from backend `/api/teams` and `/api/leagues`.
- Sports catalog comes from `GET /api/config/sports`. Team search uses `GET /api/teams/search`.
- Joining a team (`POST /api/teams/{id}/join`) is leaderboard membership. Following a team is a separate social action. Starring an HQ club (`PUT /api/me/starred-teams/{teamId}`) is a bookmark, capped at 50, and is neither a join nor a follow.
- Fetch one team with public `GET /api/teams/{id}` (id first, then slug). Archived teams return `404`.
- Leaderboard displays and team-scoped ranking views align with backend leaderboard contracts.
- Favorite-team interactions influence quest and leaderboard context where backend eligibility requires it.

## Native media, widgets, and calendar

- **Locker-room PiP:** the full-screen media viewer and inline video tiles opt in with `allowsPictureInPicture`. Inline tiles preserve active PiP playback when they leave the viewport or Reduce Motion is enabled. This is not an app-wide PiP guarantee for every video surface.
- **Rank and Fan Rep widgets:** `widgets/ios/RankOrPointsWidget.tsx` supports small/medium Home Screen layouts and circular, rectangular, and inline Lock Screen accessories. The small layout initially prefers a valid team rank. On iOS 17+, when both stats exist, its metric-toggle button switches between **Team rank** and **Fan Rep** inside the extension, even without the host app running. Medium layouts have a refresh button; Lock Screen accessories have no buttons. Taps outside buttons retain the supplied `engagenative://` deep link, otherwise opening the leaderboard for a valid rank or the wallet as fallback.
- **Live status widget:** `widgets/ios/LiveStatusActivityWidget.tsx` opens the match for a supplied `gameId`, otherwise the locker room. Its small layout keeps the **LIVE** label on one line. On iOS 17+, its medium layout has a refresh button; small and Lock Screen layouts do not. WidgetKit Home/Lock Screen layouts remain separate from ActivityKit Live Activities and Android widgets; keep platform-specific imports.
- **Widget refresh limits:** button callbacks reload App Group timeline data without inventing a new update timestamp. When the host listener receives a refresh event, it rewrites the cached rank/Fan Rep or live-game snapshot, not a fresh server response. Without a live snapshot it leaves retained final/APNs cards intact. These controls do not guarantee current scores/rank or schedule a network fetch. The metric toggle changes widget props, not account settings.
- **Scan Arena QR control:** on iOS 18+, you can use the control in Control Center, Lock Screen quick actions, or supported Action Buttons. It launches the app at `engagenative://leaderboard/scan-qr` through normal auth/onboarding gates. It does not scan or submit a check-in inside the control. This uses the existing widget target and is separate from the Siri shortcut. A rebuilt binary is required; see [widget configuration](/repositories/d-sports-engage-native/architecture#widget-controls-and-interaction-configuration).
- **Add to calendar:** upcoming HQ cards and pre-game match actions open the system event editor on iOS/Android, not web. `lib/hq/add-to-calendar.ts` builds an event from the fixture start time with a 150-minute duration, optional venue, match deep link in notes, and a 30-minute pre-game alarm. Invalid dates or unavailable APIs do not create an event. The helper distinguishes saved, opened, canceled, and error outcomes: Android's `done` response means the editor was opened, not confirmed saving. There is no silent calendar write or server-side calendar synchronization.

See [native configuration](/repositories/d-sports-engage-native/architecture#native-configuration-and-ios-capabilities) for plugins, privacy declarations, and build requirements.

## Share Extension drafts

On iOS 17+, the system share sheet can hand plain text, one HTTP(S) URL, and up to four photos to **D-Sports Engage**. The extension keeps the first nonempty text and first supported URL. It downscales photos to a maximum 2048-pixel dimension and converts them to JPEG at quality 0.85. Original formats are not preserved. Videos and arbitrary files are not supported. There is no explicit input-byte-size or text-length cap in the extension; large photos are downsampled rather than rejected by a fixed byte threshold.

Activation rules limit eligible shares. If extra images still arrive, intake skips images beyond four. Unsupported/unreadable items are skipped. If nothing usable remains, or App Group access/manifest writing fails, the extension closes without an error message or opening the app. Otherwise it saves a local handoff and requests the app's `/share-inbox` route. Only the handoff ID travels in the URL, not shared content.

The route waits for authentication/onboarding, validates the handoff, and opens **Locker Room** with the composer prefilled. Text and URL are combined without duplicating a URL already in the text. Imported text/media replace the composer values; server-draft restoration is suppressed for that opening. You still review and submit the post yourself. The extension does not upload or publish content.

Missing, invalid, empty, expired (over 24 hours), or unavailable-native handoffs fall back to **Locker Room** without a shared draft. Thrown intake failures are logged, not shown as a toast. Photo-staging failures preserve the original App Group handoff but do not automatically retry. Shared and temporary directories receive stale cleanup; the pending composer queue is in memory and does not survive app termination. This is an iOS extension, not an Android/web share target. You need a rebuilt binary with the target, entitlements, and bridge; see [Share Extension configuration](/repositories/d-sports-engage-native/architecture#share-extension-configuration).

## Tier 2 iOS behavior

- **App Shortcuts:** Open Packs opens the wallet; Scan Arena QR opens the leaderboard scanner; Live Score opens a validated explicit match ID or the tracked live match, falling back to `/hq`. The shipped Swift Live Score shortcut supplies no ID. These actions open the app and navigate; they do not open packs, submit check-ins, or speak a fetched score. Pending invocations wait for the in-app auth/onboarding gate; a burst navigates to the newest recognized target, and unknown intent names have no target.
- **Live Game accessory:** a tracked live snapshot shows a score/status bar above native tabs, or a compact inline score beside minimized tabs. Tapping opens the match. While mounted, it fetches the tracked match through existing `GET /api/events/{id}` immediately, every 30 seconds while active, and on foreground. Network failures keep the last score; final, canceled, or postponed games clear the accessory while preserving the MMKV snapshot for ActivityKit cleanup. It does not discover live matches.
- **Preview and share:** market `ListingCard` and `TradeListingCard`, plus the team browse card's details link, use `Link.Preview` and open/share menus for native iOS interactions. Sharing strips Expo route groups and defaults to `https://app.d-sports.org`; the team share action requires a string href. This is not an app-wide preview or external metadata service.
- **Sheets and resizing:** HQ game summaries and the legacy wheel/player-guess routes use native iOS form-sheet detents. Match routes and engine game routes are not converted wholesale. Large iOS media-viewer windows remain free of programmatic orientation locking under the 600-dp shortest-side heuristic; compact iOS and Android keep existing viewer behavior.

## Alternate app icons

On a supported iOS device and binary, open **Settings → Appearance → App icon** (`/settings/app-icon`). Choose **D-Sports**, **D-Sports Gold**, **HC Sierre**, or **Milano HC**. These are the entire curated roster; following or joining a team is not required. The app does not automatically select your favorite team, download more icons, or accept custom artwork. **D-Sports** restores the primary Icon Composer icon; the alternate PNGs do not replace that default bundle.

PR #1411 replaces the former London Knights and Oshawa Generals options with D-Sports-themed **HC Sierre** (crimson and gold) and **Milano HC** (navy, crimson and gold) artwork. **D-Sports Gold** remains available. The team names are untranslated brand labels; default/Gold labels and option descriptions follow the app's English, French, or Italian settings translations.

The picker reads the current native icon, disables choices while a switch is pending, and shows a spinner. After iOS reports success, the selected marker and Appearance row update. Selecting the active option does nothing. A failed switch keeps the prior selection, logs the failure, and shows a localized error banner. The choice is device-level native state, not an account preference synchronized through the API.

There is no app-side migration or automatic reset for a removed icon selection. If iOS still returns a removed native icon name, the Appearance row displays the **D-Sports** fallback label/preview, but the picker has no selected row because it compares the raw native name with the current options. Choose **D-Sports** to explicitly request the primary icon, or choose a current alternate. The implementation/tests do not establish whether iOS itself preserves or resets removed artwork during an app upgrade.

The Appearance entry is hidden when the device/binary does not support alternate icons. Direct entry to the picker shows unsupported copy. Android, web, Expo Go, and older binaries without the module do not switch icons. The module and all icon artwork must be installed in a new native binary; OTA cannot add compiled icons. See [alternate icon configuration](/repositories/d-sports-engage-native/architecture#alternate-app-icon-configuration) for assets, build settings, and tests.

## Home Screen Quick Actions

After the iOS app registers its dynamic shortcuts, long-press its Home Screen icon to access these four actions in catalog order. Titles follow the app language (English, French, or Italian) and refresh on app mount and locale changes. There is no static pre-first-launch menu fallback or personalized live-match list.

| Action | Destination | Behavior |
| --- | --- | --- |
| **Live Game** | `/hq` | Opens HQ, not the tracked match. #1406 removes the former `teamHqEnabled`/dev-label client lock, so HQ is open to all fans. |
| **Open Packs** | `/market/packs` | Opens the pack market, not the wallet; it does not open or buy a pack. |
| **Scan Arena QR** | `/leaderboard/scan-qr` | Opens the scanner; it does not submit a check-in automatically. |
| **Market** | `/market` | Opens the market without performing a transaction. |

Warm taps navigate immediately when you have passed authentication/onboarding, using `router.navigate` to avoid duplicate screen stacking. Cold taps are buffered natively until the listener attaches. If the in-app gate is closed, the target waits in the pending-deep-link helper until the gate opens. Only the latest buffered/pending target is retained; this is not a durable queue. Unknown IDs are ignored, and normal route/backend authorization still applies.

These app-icon actions are separate from Siri shortcuts and widget buttons. They require an iOS binary containing the local Quick Actions module; Android, web, Expo Go, and older binaries do not register them. Later JS-only labels/catalog/routing updates can use a compatible OTA, but OTA cannot add the native module. See [Quick Actions configuration](/repositories/d-sports-engage-native/architecture#home-screen-quick-actions-configuration) for registration, limits, and tests.

## Android AppSearch and AppFunctions

PR #1423 indexes teams from `user.favoriteTeams`, active-wallet binder summaries, and owned collectible cards after authenticated in-app routes become active.
The shared mappers cap the batch at 250 items in team, binder, then card order.
Posts and marketplace listings are not indexed.
Binder mutations and foregrounding refresh binder summaries.
Wallet changes and fetch failures clear stale binder rows.
AppSearch uses platform storage on API 31+ when available, with local storage on older supported devices or platform failure.
System search visibility depends on the device/provider; local storage alone does not deliver system search results.

Android 16+ exposes these declarations in `appfunctions/BaseDSportsAppFunctionService.kt`:

| Function | Result and limits |
| --- | --- |
| `getLiveScore(teamId?)` | Reads one cached live/recent HQ score with a match launch handle. Optional normalized text matches cached team slug, names, or abbreviations. A mismatch throws element-not-found. Missing cache returns `hasLiveGame: false` and an HQ launch handle. A safe match ID opens match detail and retains a safe context slug. |
| `getFanRep()` | Reads cached signed-in Fan Rep, optional rank/name, a summary, and a leaderboard launch handle. Missing signed-in cache throws element-not-found. |
| `openArenaQr()` | Returns scanner metadata and a launch handle. It does not scan, check in, or award Rep. |
| `searchCollectibles(query, limit)` | Prefix-searches only indexed cards. Blank queries throw invalid-argument. Nonpositive limits default to 10; positive limits cap at 50. Returns the first result page with metadata and card launch handles, or an empty list for no matches. |

The immutable launch handles target this app's package and `engagenative` routes.
Normal routing and authentication gates still apply.
They do not silently execute protected actions or transactions.
Declaring these functions does not guarantee Gemini or another assistant will discover or invoke them.

`lib/android/app-functions.android.ts` mirrors profile Fan Rep and HQ snapshots into private native SharedPreferences.
`lib/hq/widget-sync.android.ts` updates the score and clears it when `clearHqWidget` receives an ended match.
The service reads this cache and AppSearch without booting React Native JS or fetching network data.
Timestamps are stored but no freshness TTL is enforced.
Answers can be stale; they are not live backend lookups.
Sign-out, account deletion, settled signed-out startup, and account switching request index/cache cleanup.
Cleanup failures are not a guarantee of immediate OS deletion.
Non-Android wrappers and missing native modules no-op.

See [Android integration](/repositories/d-sports-engage-native/architecture#android-appsearch-and-appfunctions-integration) for schemas, identifiers, native dependencies, rebuild requirements, and tests.
Compare [iOS Spotlight](#spotlight-search-and-handoff) and [iOS App Intents](/repositories/d-sports-engage-native/architecture#tier-2-native-integration).
The Android implementation does not add Handoff or a new API contract.

## Spotlight search and Handoff

On iOS, the authenticated in-app bootstrap indexes teams from `user.favoriteTeams`, active-wallet binder summaries, and owned collectibles using existing data sources. Binder mutations and foregrounding refresh binder summaries; wallet changes clear stale binder rows. Posts and marketplace listings are not part of the Core Spotlight batch.

Team search results open `/hq/{slug}`; binder results open `/binder/{id}`; card results open `/binder`, not a selected card. Continuations wait for the in-app gate. The parser accepts Engage identifiers, internal paths, and HTTPS URLs on the configured or canonical app host, rejecting other schemes/hosts. Route guards and backend authorization remain authoritative.

Focused HQ clubs, non-global team boards, binder/card detail, visible or owned market listings, and ready post detail publish Handoff activities. The activity clears on blur. Sign-out, settled signed-out/session-revoked startup, and account switching invoke index and activity cleanup, including cancellation of pending index updates. Native failures are logged; cleanup is not a guarantee of synchronous OS deletion. Handoff offers continuation, not cross-device state synchronization or a new search API.

See [Tier 2 configuration](/repositories/d-sports-engage-native/architecture#tier-2-native-integration) and [Spotlight integration](/repositories/d-sports-engage-native/architecture#core-spotlight-and-handoff-integration) for source ownership and native-build requirements.

## Apple Wallet passes

The **Add to Apple Wallet** button is available on the fan's own profile for a Fan ID, eligible team leaderboards for club membership (the existing `showAlertsBell` gate plus a team ID), and HQ match bodies for an arena-event pass. It is hidden when signed out, on Android/web, in older binaries without the native module, and where PassKit cannot add passes.

On tap, the hook prevents concurrent requests, fetches a signed pass through the authenticated API client, and presents Apple's native confirmation sheet. The client does not generate/sign passes or add them silently. Native completion checks whether the pass is in Wallet; dismissing the sheet is not itself success. The hook can recheck the returned identity, updates local added state, and shows localized success/error feedback, including a configuration message for a 503. The shipped CTA does not supply the optional known-pass identity for an initial Wallet check, so added state is not a persistent cross-mount status cache. There is no automatic pass refresh. Android has a separate Google Wallet integration below.

See [native configuration](/repositories/d-sports-engage-native/architecture#apple-wallet-pass-configuration) for the module and entitlement. The issuance contract is owned by [d-sports-api PR #1167](https://github.com/D-Sports-Ecosystem/d-sports-api/pull/1167) and [Platform and infrastructure API](/api-reference/domains/platform-infra).

## Google Wallet passes

PR #1421 adds **Add to Google Wallet** on Android at the same three entry points as Apple Wallet:

| Pass | Source and entry point |
| --- | --- |
| Fan ID (`fan_id`) | Your own profile, `features/profile/screen/OwnProfileScreen.tsx` |
| Club Membership (`club_membership`) | `components/leaderboard/TeamLeaderboardScreen.tsx`, gated by `showAlertsBell` and a team ID |
| Arena Event (`arena_event`) | `features/hq/screen/HqMatchBody.tsx`, with game ID and optional context team ID |

`AddToGoogleWalletButton.android.tsx` uses `hooks/use-google-wallet-pass.android.ts` to prevent concurrent taps, request a server-signed pass, and present the native save flow. The CTA is hidden when signed out or after an explicit `503 CONFIGURATION_ERROR`; the latter shows localized configuration feedback. Other failures, including `503 RATE_LIMITER_UNAVAILABLE`, show an error without hiding the CTA. iOS/web stubs render nothing. Missing native support or unavailable Play Services still permits the Android browser fallback.

Only native `saved` sets the mounted hook's added state and success feedback. Cancellation is silent. Native `error` shows an error without opening the browser. If availability is false or native save returns `unavailable`, the hook opens the validated Save URL. Browser opening does not confirm saving or set added state. There is no persistent Wallet membership check, automatic refresh, or pass-update push integration. Saving an event pass does not check you in, and the client does not sign passes.

See [native configuration](/repositories/d-sports-engage-native/architecture#google-wallet-pass-configuration) and [native integration](/repositories/d-sports-engage-native/integration-contracts#google-wallet). ## App Clip

An arena invocation such as `https://app.d-sports.org/clip/arena/<id>` opens the iOS 17+ **D-Sports Arena** clip without installing full Engage. Its SwiftUI card displays a public event/club preview, including available team branding, status, venue/start time, and match scores. It does not sign you in, subscribe to live scores, claim a check-in, or award Rep. Invalid links, missing arenas, and network/server failures show **Couldn't Load Arena**; **Try Again** appears when a valid arena ID was extracted. API requests use 10-second request and 15-second resource timeouts.

Choose **Check In & Earn Rep in Engage** when check-in is available, or **Open in D-Sports Engage** otherwise. The clip saves the latest arena/team/game context and requested-check-in flag in the shared App Group, then presents the App Store installation overlay. A successful save displays confirmation. The overlay still runs if saving fails, so installation alone does not prove the context was saved. **Get App** presents the overlay without writing a new arena handoff.

After you install/open Engage and complete sign-in/onboarding, the app validates the saved payload. It discards malformed/empty payloads, invalid IDs/kinds, payloads older than 24 hours, or timestamps over one minute in the future. Games open `/hq/match/<id>`; partner clubs open `/(tabs)/leaderboard/<slug>`; non-partner clubs open `/hq/<slug>`. It derives destinations locally rather than trusting the saved URL. A requested check-in with a team ID runs through the authenticated quest client. Success or an already-claimed result sets the arena badge and clears the handoff; success also shows earned Rep. Other errors show feedback, log the failure, and retain the payload for a later effect retry, not a timed background queue. Navigation-only handoffs clear after routing.

If full Engage is already installed, incoming clip links instead queue the latest arena ID in memory and land on `/`. The app waits for the same auth/onboarding gate, fetches the public preview, and opens the appropriate route without automatically checking in. This URL-only pending ID is consumed before fetching and is not durably retried on failure. The App Group holds only one saved payload, not a history of visits.

See [App Clip configuration](/repositories/d-sports-engage-native/architecture#app-clip-configuration) for target, signing, native-build, size-validation, and test limits. For server-owned preview/check-in behavior and AASA, use [Platform and infrastructure API](/api-reference/domains/platform-infra) and [Platform behavior](/repositories/d-sports-api/platform-infra/behavior).

## Android Tier 1 platform behavior

### Video, back navigation, and sign-in association

Supported Android devices can use platform PiP from the native controls on Locker Room inline videos and the media viewer. Active inline PiP is exempt from viewport/Reduce Motion pausing; this is not automatic PiP on every video or a separate background-media service. Predictive back enables the system's supported edge-back previews rather than custom screen animations, and keeps existing route/auth guards. Compare [iOS video behavior](/repositories/d-sports-engage-native/feature-mapping#native-media-widgets-and-calendar).

Passkey changes are Digital Asset Links plumbing, not a new sign-in button, enrollment flow, or auth bypass. Website statements, installed signing identity, OS/provider support, and the existing auth implementation remain separate requirements. No application caller invokes the installed passkey library in this change.

### Per-app language

Android system **App Languages** (API 33+) and the in-app language preference synchronize English, French, and Italian choices. Startup imports the system choice before the first mirror so a choice made while Engage was closed is not overwritten; foreground resume imports again. Older Android uses AppCompat APIs, not a promise of the same system settings UI. Unsupported/empty language tags use device-following; the preference is device-local and does not require sign-in. Missing native support skips synchronization; errors log warnings.

### Launcher shortcuts

Long-press the app icon to access the four packaged static shortcuts, subject to launcher support. Their generated labels are English:

| Label | Target and limits |
| --- | --- |
| **Live Game** | `engagenative://hq` opens HQ, not a selected tracked match. |
| **Packs** | `engagenative://(tabs)/wallet` opens the wallet without opening/buying a pack. This differs from the iOS **Open Packs** Quick Action's pack-market destination. |
| **Arena QR** | `engagenative://(tabs)/leaderboard/scan-qr` opens the scanner without submitting a check-in. |
| **Market** | `engagenative://market` opens the marketplace without a transaction. |

After sign-in/onboarding, dynamic requests include **Locker Room** (`engagenative://(tabs)/locker-room`) and up to three unique favorite clubs resolved through the teams catalog (`engagenative://hq/<slug>`). Club labels use the catalog name, truncated to 18 characters. The launcher may show fewer or none: static shortcuts consume quota first. The same dynamic entries are long-lived Direct Share candidates, not guaranteed share-sheet placement. Sign-out after an authenticated session removes dynamic entries, not packaged static or pinned shortcuts. Pin APIs exist for a club/scanner, but no product UI calls them.

These intents use normal Expo Router/deep-link auth handling, not the [iOS Quick Actions](/repositories/d-sports-engage-native/feature-mapping#home-screen-quick-actions) forced pending-route path. The pending-link helper does not restore explicit `(tabs)` routes, excludes public HQ paths, and ignores hostname-only targets in its capture helper. Do not assume every destination survives a cold signed-out onboarding flow.

### Share into Locker Room

Use Android's share sheet to send text/links, images, or videos into Engage. The full app handles cold/warm/resume intents; unlike the [iOS Share Extension](/repositories/d-sports-engage-native/feature-mapping#share-extension-drafts), it does not use a separate extension or App Group. It takes the first four media streams, copies accepted images/videos into temporary private cache, and skips unreadable/unsupported files or files over 50 MiB. It does not transcode/downsample, import arbitrary files, or show per-file rejection feedback. Text and surviving media can still form a draft; completely empty imports do nothing.

The client trims/deduplicates subject/text and keeps one pending draft in memory. Signed-out/onboarding fans wait until the authenticated in-app gate opens; warm authenticated shares navigate to **Locker Room** immediately. Only the focused Locker Room screen auto-opens the composer. Its personal-draft scope consumes the text/media before server-draft fallback. Direct Share carries a shortcut ID but does not select a team/channel. Nothing posts automatically: normal composer/upload/posting rules remain. Later shares replace pending content, process death loses the handoff, and cached files may be pruned after ten minutes when later copies run. This is not a durable multi-share inbox.

### Restore Credentials and Play updates

Restore Credentials ships an Android 9/API 28+ bridge and sign-out cleanup, not automatic device-migration login. Create/get require server-provided WebAuthn JSON but have no application callers; the app does not enroll/verify a restore key or restore a Clerk session. The bridge tries E2EE cloud backup then local-only fallback when E2EE is unavailable, and handles missing providers without blocking normal sign-in. After a previously in-app user signs out, the host clears the local synced flag and requests deletion of the restore credential.

For eligible Play-installed builds, the authenticated app's existing forced/soft update gate can start a Play update. Forced prefers immediate when allowed, otherwise flexible; soft uses flexible only. On flexible download completion, **Update ready** offers **Restart**; only choosing it completes the update/restarts, rather than silently restarting over a composer draft. This is not a guarantee of draft persistence after an approved restart. Foregrounding can re-prompt for a downloaded update or resume an immediate update. Non-Play/sideload/debug errors return unavailable/false through this wrapper; it does not disable other update-gate behavior. This flow installs a native Play build, not an Expo OTA.

See [Android configuration](/repositories/d-sports-engage-native/architecture#android-tier-1-configuration) for plugins, native-build/OTA boundaries, test coverage, and unverified device/Play behavior.

## Android Tier 2 platform behavior

### Material 3 navigation

The Android tab bar is now a floating Compose capsule with native ripples, selected-tab semantics, scaled labels, and API 31+ live backdrop blur. Its five entries still open the existing wallet, shop, Locker Room, leaderboard, and profile tab routes through normal auth/onboarding gates. The wallet badge shows sealed owned packs, capped at **99+**. Hide/show follows the shared navigation visibility with an Expressive spring, or snaps with Reduce Motion. The host supports wallpaper-derived colors on capable devices and follows the app's dark/light choice, but the capsule keeps explicit gold/neutral styling. This does not migrate every screen: new loading, sheet, and snackbar wrappers are not called by product screens.

### Quick Settings tiles

Add tiles with Android's Quick Settings editor; Engage does not auto-place them or expose an in-app add button. **Scan Arena QR** opens `engagenative://leaderboard/scan-qr`; its **Check in** subtitle does not mean a check-in is submitted. **Live Game** opens `engagenative://hq/match/<encoded-id>` (optional encoded `slug`) when its cached snapshot is active with an ID. Otherwise it opens `engagenative://locker-room` and shows **Open Locker Room**. Tile labels are currently English resources; an active tile can show the cached score/status.

Locked taps request device unlock, then launch the app through existing route/auth guards. They do not run the scanner inside the shade, bypass sign-in, or guarantee every cold signed-out destination is restored. State comes from foreground match polling or a successful headless HQ refresh, not a separate live tile subscription. Leaving a live screen preserves the tile snapshot; an observed final clears it on the ended-game path. There is no separate sign-out/expiry cleanup, so an apparently active tile can be stale. Compare the [iOS Control Center scanner](/repositories/d-sports-engage-native/feature-mapping#native-media-widgets-and-calendar).

### Widget refresh

The **D-Sports Rank** and **D-Sports Live** widgets gain a **Refresh** (`↻`) action without opening the app. Live widgets show last-play text when space permits. Ordinary widget body taps keep their existing app/deep-link behavior. Refresh attempts a four-second-budget snapshot fetch, then redraws stored data. Initial/periodic/resize renders remain cache-based, and Android controls update scheduling.

Do not treat the refresh button as proof of fresh authenticated scores/rank. The shipped helper omits the API's required bearer header and does not unwrap its `data` response envelope. Missing configuration, rejected requests, timeout/offline/errors, or absent expected fields leave local/push data without an error banner. It does not open a login flow or bypass API authorization. Compare [iOS widget refresh](/repositories/d-sports-engage-native/feature-mapping#native-media-widgets-and-calendar), which rewrites cached snapshots without this Android network attempt.

### Live Update colors

On Android 17/API 37+, eligible live-game ProgressStyle notifications can use blue info, red urgent, or green final accents/milestone points. Team-color segments stay unchanged; neutral and older Android keep existing styling. A valid explicit `semanticTone` wins; absent/invalid values fall back to status/last-play text heuristics (FINAL/FT, OT/SO or GOAL, PP/INT, otherwise neutral). The color is a hint, not authoritative game state, a new follow subscription, or a guarantee of SystemUI promotion. Existing notification consent, delivery, and tap routing remain in force. The [iOS Live Activity contract](/repositories/d-sports-engage-native/integration-contracts#game-center-contracts) remains a separate ActivityKit surface, not an Android widget/color feature.

### Notification categories and photo selection

Android registers five channel categories: `hq_goal_alerts` (high, no badge, goal-horn vibration), `hq_quiet_updates` (low, silent/no badge), `dsports_quest_drops` (default, badge, two-tap pulse), `dsports_marketplace_bids` (high, badge, double-tap), and `dsports_locker_room_replies` (default, badge, light tap). New category names/descriptions have English/French/Italian entries. Android/user settings control actual sound, vibration, and importance; existing channels are not reset by an app update. Registration alone neither grants notification consent nor makes server pushes target those categories. A channel-settings helper exists, but no in-app screen calls it. See the shared [settings/notification contract](/repositories/d-sports-engage-native/integration-contracts#settings-and-notifications) for account preferences; iOS does not use Android channel IDs.

Binder cover selection/uploads and admin artwork now open Android's system library picker without first requesting broad media-library permission. Access is limited to selected media; normal cancellation/upload handling and admin edit gates still apply. The build blocks broad image/video and legacy read-storage permissions, while deliberately retaining legacy write-storage support for API 26–28 camera use. Non-Android permission handling is unchanged. This is not a whole-library browser, new camera entitlement, or verified Play approval.

See [Tier 2 configuration](/repositories/d-sports-engage-native/architecture#android-tier-2-configuration) for native-build/OTA boundaries, source tests, and device-verification limits.

## Notifications and legal

- Push delivery uses OneSignal. In-app inbox uses `/api/notifications*` and includes `GAME_ALERT` and `RATING`.
- Settings persist per-channel notify flags on `PATCH /api/user/settings`.
- About can check for an EAS OTA update without waiting for the next cold start.
- Locker-room posting gates on the in-app EULA. Policy pages render in-app; do not hardcode legal copy in clients.
- Accessibility settings include high contrast and color-blindness palettes. The public support matrix is `GET /api/accessibility`.

## Admin hub

- `app/(admin)` exposes team-manager surfaces: packs, collectibles, coins, games, live, moderation, social, submissions, team access, users, and CMS.
- The client gate is UX only. Every `/api/admin/*` route re-checks RBAC server-side.
