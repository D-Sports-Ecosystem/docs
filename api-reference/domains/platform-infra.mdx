## Scope

Platform APIs include utility routes that support app infrastructure or cross-domain behavior.

## Endpoint map

- Utility and media: `/api/image-proxy`, `/api/upload/banner`, `/api/upload/binder-cover`, `/api/upload/locker-media`, `/api/upload/profile`
- Liveness: `GET /api/health` (no auth, no database)
- Public sports catalog: `GET /api/config/sports` (see [Teams and leagues](/api-reference/domains/teams-leagues))
- Public accessibility matrix: `GET /api/accessibility` (used by native and the marketing site)
- Notifications inbox: `GET /api/notifications`, `POST /api/notifications/{notificationId}/read`, `POST /api/notifications/read-all`, `POST /api/notifications/{notificationId}/archive`. Types include `GAME_ALERT` and `RATING`.
- Behavioral feed ingest: `POST /api/feed/signals` (authenticated). The server drops the payload when `UserSettings.analyticsPersonalization` is false. Opted-in batches are stored as `FeedSignal` rows: at most 50 events, a 64KB body, and 30 batches per minute (`429`). The response includes `accepted`. The operation description covers the body; there is still no `requestBody` schema.
- Platform status/data surfaces: `/api/dashboard`, `/api/dashboard/stats`, `/api/dashboard/balance`, `/api/dashboard/quests`
- Apple Wallet passes: `POST /api/v1/passes/apple-wallet` (authenticated) signs a `.pkpass` for the caller. Send `passKind` (`fan_id` default, `club_membership` with the `teamId` of an Engage partner club you have joined (a non-partner or unjoined club returns `403`; an unknown `teamId` returns `404`), or `arena_event` with `gameId` and/or `teamId`) and `format` (`binary` default, or `base64` for `PKAddPassesViewController`). Binary responses are `application/vnd.apple.pkpass` with `Cache-Control: no-store`. Unknown fields return `400`, bodies over 4 KB return `413`, and the route returns `503 CONFIGURATION_ERROR` until pass signing is configured.
- App Clip arena preview: `GET /api/v1/app-clips/arena/{id}` (no auth) accepts a game event ID, team ID, or team slug and returns a public-only card: title, venue, status, start time, team colors and logo, `checkInAvailable`, `fullAppUrl`, and `checkInEndpoint`. `checkInAvailable` is true only for an Engage partner club with a non-demo fixture in the arena check-in window (for a club ID, a home fixture). A game preview checks only the home club. The claim API can accept an eligible away club, but [Engage preview flows](/repositories/d-sports-engage-native/integration-contracts#apple-wallet-and-app-clip-contracts) only use the preview's home club and skip the claim when the flag is false. The preview sends a weak `ETag` and returns `304` when `If-None-Match` matches the current one, returns `400` for a malformed ID and `404` when nothing matches, and never writes. Check-in stays on authenticated `POST /api/v1/engage/quests/arena-check-in`.
- App links: `/.well-known/apple-app-site-association` also lists the App Clip `LU58V6484P.com.dsports.wallet.beta.Clip` under `appclips` and the `/clip`, `/clip/*` paths. Both `.well-known` files are public.
- Maintenance utility: `/api/sync-quest-points`
- Integration sync references: `/api/webhooks/leagues-sync` (behavior reference), admin sync triggers documented in domain guides

Unknown `/api/*` paths return JSON `404` with code `NOT_FOUND`. They do not fall through to the HTML app 404.

## Integration notes

- Some utility routes are intended for specific client contexts; avoid treating all as generic public services.
- Keep route usage aligned with deep-dive operational guidance.
- Internal cron/debug operations are intentionally excluded from public API docs.
- Teams/leagues sync internals are documented in public-safe terms only.
- The [shared AI foundation](/repositories/d-sports-api/platform-infra/architecture#shared-ai-sdk-foundation) is server-side infrastructure, not a new API endpoint.

| `POST /api/v1/passes/google-wallet` | Clerk-authenticated pass issuance. Returns a signed Google Wallet Save URL and JWT, not a pass file. |

## Widget API

| Endpoint | Contract |
| --- | --- |
| `POST /api/v1/widgets/token` | With a Clerk session, send `deviceId` (a stable per-install ID) and `platform` (`android` or `ios`). A `201` returns an opaque `wgt_` bearer and expiry once. Issuing again replaces that installation’s token. |
| `GET /api/v1/widgets/snapshot` | Use a Clerk session or send a widget bearer. Returns global rank, Fan Rep, and HQ Live. Add `?include=clubs,wallet,packs` to request club game summaries, the D-Sports Cash balance, and unopened packs and free-pack allowance. Request only the slices you need. |
| `DELETE /api/v1/widgets/token` | Present the widget bearer to revoke itself, or use a Clerk session with the device ID in the query or JSON body. |

Keep the widget bearer in secure device storage. Revalidate the same user’s snapshot and query by sending the returned weak `ETag` in `If-None-Match`. A `304` has no response body; keep the cached snapshot. When the response includes a free-pack allowance, its cache lifetime is capped at the next UTC reset. See [widget snapshot behavior](/repositories/d-sports-api/platform-infra/behavior#widget-snapshot) for field details, optional read failures, and cache rules.
